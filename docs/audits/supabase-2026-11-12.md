1. **High: chat attachment RLS allows access across groups and prevents recipient access.** The deployed policy `Users can view attachments they sent or received` allows any `agent` or `supervisor` to read a chat object without checking group, assignment, or conversation membership. For a regular customer it checks only the first path segment against their own user ID. The application uploads files beneath the sender's ID, so a customer cannot obtain a signed URL for an attachment sent by their agent. The policy also has no `group_admin` branch. The upload policy checks authentication but does not enforce ownership of the destination folder.

   Both main failures were reproduced with synthetic accounts and files in the isolated database using the deployed policy definitions: an unrelated agent could select another group's object, while the intended customer recipient could not select their agent's attachment. Production currently has zero storage objects, so no real private file was accessed during this audit. Repair the SELECT policy using actual message participants and authorized CRM scope, and enforce the uploader's allowed folder in the INSERT policy. Check single and multiple attachment representations used by `useMessages.tsx` before implementing the participant lookup.

   Sources: [storage policy migration](../../supabase/migrations/20251223144817_c992bffc-f2e3-456a-8217-d02d946a38d8.sql), [attachment upload and signed URL code](../../src/hooks/useMessages.tsx).

2. **Medium: Realtime is missing three tables used by the frontend.** `customer_notes` and `case_timeline` are subscribed to by `CustomerDetail.tsx`; `password_reset_requests` is subscribed to by `PasswordResetRequests.tsx`. None belongs to `supabase_realtime`. The matching callbacks therefore cannot receive Postgres change events for those tables; ordinary fetches and page reloads can still retrieve their data. Add those three tables in a new migration. Publication membership is required by [Supabase's Postgres Changes setup](https://supabase.com/docs/guides/realtime/subscribing-to-database-changes).

3. **Medium: nine RPCs retain anonymous EXECUTE permission despite migration statements intended to restrict them.** Affected functions: `adjust_crypto_balance`, `adjust_fiat_balance`, `can_manage_customer`, `delete_crypto_balance`, `get_user_sessions_for_staff`, `review_kyc_submission`, `save_kyc_submission`, `set_balance_dashboard_visibility`, and `set_managed_user_role`.

   This is a source hardening gap, not proven post-migration drift. The project explicitly grants EXECUTE to `anon` through default privileges; revoking from `PUBLIC` alone does not remove that separate grant. Replaying the migrations with the observed Supabase defaults reproduces the live ACLs exactly. Revoke EXECUTE from both `PUBLIC` and `anon` on these functions while preserving authenticated and service-role access. Their existing authorization checks still matter: this audit did not demonstrate anonymous balance changes or role escalation. See [Supabase's function privilege guidance](https://supabase.com/docs/guides/database/functions).

4. **Production configuration: Auth URLs are still local.** Live `site_url` is `http://localhost:3000`, and `uri_allow_list` is empty. Configure the actual deployed portal URL and the exact callback URLs used by the application before relying on password recovery links, invitations, OAuth, or other Auth redirect flows. The repository and supplied credentials do not identify the intended production domain. Email/password signup is enabled and email confirmation is disabled, matching `supabase/config.toml`. See [Supabase's redirect URL configuration](https://supabase.com/docs/guides/auth/redirect-urls).

Empty input to MFA and market endpoints returned the expected HTTP 400 application validation errors. - The proposed RPC/Realtime remediation SQL was applied twice in isolation to verify repeatability. All nine targeted anonymous EXECUTE permissions were removed, authenticated and service-role execution remained available, and publication membership increased from nine to 12 tables.
